😓 The Problem — Manual Backports Are Painful

  • ⏱️ 25–30 minutes per backport. Every single time — create branch, cherry-pick, open MR, set reviewers, labels, write Jira comment, transition status.
  • 🧠 Mental overhead. You need to know the exact release branch, fix version format, GM2 run history, Jira workflow states, and comment template — all from memory.
  • ❌ Human error. Wrong branch target, missed reviewers, forgotten Jira transitions, or stale GM2 data slip through — causing delays or rejected backports.
  • 🔍 Test ID hunting. Finding the right TC / Xray IDs from diffs, MR descriptions, and Jira tickets is tedious and inconsistent across engineers.
  • 📉 Context switching. Each backport pulls an engineer out of their actual work — GitLab tab, Jira tab, OpenSearch tab, repeat.
  • 🔁 Multiple releases = multiple repetitions. A single Jira ticket can require backports to 2–3 release branches — multiplying the manual effort.

⚡ The Solution — One Command Does Everything

# Phase 1 — Safe dry-run (read-only, always run first)

# Phase 2 — Execute when Phase 1 shows BACKPORT ELIGIBLE
PS C:\Working_Env\...> python backport.py --mr 91281 --execute

📊 GM2 Eligibility Check — Strict Rules

Run Pattern → Verdict

Run PatternEligible?
… → PASS → PASS✅ YES
FAIL → PASS → PASS✅ YES
PASS → FAIL → PASS❌ NO
PASS → PASS → FAIL❌ NO
Less than 2 runs❌ NO

Qualifying Run Filter

  • 🔎 Environment = GM2 only — no GM1/sandbox runs counted
  • ⏱️ Post-merge only — runs after the MR merge timestamp
  • 🚫 rerun_count = 0 — re-run attempts excluded
  • 🚫 isCBB = false — CBB executions excluded
  • 📋 Last 2 of 50 fetched — most recent pair decides eligibility
⚠️ All test cases must pass.
One ineligible ID → DO NOT BACKPORT

🔓 GM2 Bypass Options

🌐 Global Bypass

Skips GM2 check entirely for all test cases. Use when the pipeline or smoke suite is broken and blocking a critical fix.

python backport.py --mr 91281 --execute \
  --bypass-gm2 \
  --bypass-gm2-reason "Smoke failure blocking release"

All TCs marked BYPASSED in the Jira comment with the reason.

🎯 Selective Per-TC Bypass NEW

Bypasses only the specific failing test IDs you name. All other IDs still go through normal GM2 eligibility. For known flaky tests or issues unrelated to the fix.

python backport.py --mr 91281 --execute \
  --bypass-gm2-for TC-1234 DEV-5678 \
  --bypass-gm2-for-reason "Known flaky, env issue"

Or skip the flag — the script prompts interactively when a test fails:

  TC-1234: Passed → Failed → [NOT ELIGIBLE]
    Reason: Latest two runs not both PASS
    Bypass GM2 check for TC-1234? (y/n): y
    Enter bypass reason for TC-1234: Known env issue
    [BYPASSED] TC-1234: Known env issue
✅ Bypass reason recorded in Jira comment ✅ Dashboard links still generated for non-bypassed TCs ✅ Works in CI with --non-interactive
